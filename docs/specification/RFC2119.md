# Normative Language

- Status: Draft
- Specification series: 0
- Scope: normative terminology for specification documents

## Purpose

This specification uses RFC-style normative terms to distinguish requirements from guidance, examples, and explanatory text.

## Normative terms

When capitalized, the following terms are normative:

- MUST
- MUST NOT
- REQUIRED
- SHALL
- SHALL NOT
- SHOULD
- SHOULD NOT
- RECOMMENDED
- NOT RECOMMENDED
- MAY
- OPTIONAL

Lowercase uses of these words are non-normative unless a document explicitly says otherwise.

## Requirement strength

### MUST / REQUIRED / SHALL

A conforming implementation is required to follow the requirement.

Failure to satisfy a MUST requirement is a conformance failure for the relevant profile or feature.

### MUST NOT / SHALL NOT

A conforming implementation is prohibited from doing the stated behavior.

Violating a MUST NOT requirement is a conformance failure.

### SHOULD / RECOMMENDED

A conforming implementation is expected to follow the requirement unless it has a well-understood reason not to.

An implementation that intentionally diverges from a SHOULD requirement SHOULD document the reason, interoperability impact, and safety impact.

### SHOULD NOT / NOT RECOMMENDED

A conforming implementation is expected to avoid the behavior unless it has a well-understood reason.

### MAY / OPTIONAL

The behavior is permitted but not required.

Optional behavior may still need registry entries, capability negotiation, or profile declarations.

## Normative vs informative sections

Specification documents SHOULD clearly separate normative requirements from informative examples.

Sections titled `Examples`, `Notes`, `Rationale`, `Open Questions`, or `Future Extensions` are informative unless they explicitly contain capitalized normative terms.

## Conformance scope

Normative language applies only within the scope declared by the document and the relevant conformance profile.

A MUST in an optional extension applies only to implementations that claim support for that extension.

## Use in tests

Every stable MUST or MUST NOT requirement SHOULD eventually be testable by a conformance suite, static validator, protocol fixture, or interoperability test.
